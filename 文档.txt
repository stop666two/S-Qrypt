# S-Qrypt 终极完整构建与技术文档

---

## 1. 项目概述
S-Qrypt 是一个严格零信任、后量子安全的加密笔记保险箱，专为 Cloudflare Workers 无服务器平台与 D1 边缘数据库设计，提供一键部署能力，自动完成 Worker 创建、D1 数据库绑定及初始化迁移。该系统将“永不信任服务端”的理念贯彻到极致：所有密码学运算（包括多阶主密钥派生、三条完全异构的笔记工作密钥生成、AES-256-GCM 认证加密、防篡改校验、日志签名、操作授权令牌）完全限定在用户浏览器内执行。服务器与数据库仅作为密文和公开验证令牌的透明中转站，不存储任何盐、随机种子、签名、密钥材料或明文。即使攻击者完全控制服务器并导出全部数据，也无法解密哪怕一个字节的明文，甚至无法执行未授权的破坏性操作（如删除笔记）。

本版本针对密钥生成进行了根本性强化：笔记的三个 2048 位密钥通过 **三种设计哲学完全不同的密码学构造** 分别派生，彻底杜绝简单 info 扩展的脆弱印象；同时融合了抗侧信道、沙箱隔离、透明日志、自适应性能、操作授权防越权删除等高级防护，形成端到端的军事级安全体系。

---

## 2. 核心特性
- **一键部署**：利用 Cloudflare Workers 模板，用户授权后自动创建 Worker 脚本、D1 数据库，并执行数据库模式迁移，全程无需手动配置连接字符串或数据库名。
- **绝对零信任模型**：
  - 用户密码、主密钥、三条笔记工作密钥、所有明文数据永不出浏览器。
  - 服务器 Worker 代码只实现 RESTful API，对密文和验证令牌进行存取，不包含任何解密逻辑。
  - D1 数据库不存储盐、IV（作为密文的一部分）、随机种子、签名或密钥封装材料。
- **后量子安全基础**：
  - 对称加密采用 256 字节（2048 位）密钥，根据 Grover 算法，量子计算攻击下有效安全强度为 1024 位，完全能够对抗任何可预见的量子计算机。
  - 密钥派生过程中可选配 BLAKE2b 等抗量子哈希函数。
- **三把完全异构的 2048 位笔记密钥**：
  - **KA**（元数据密钥）由回旋哈希链派生；
  - **KB**（正文密钥）由多层密钥加密构造派生；
  - **KC**（完整性密钥）由树状哈希派生。
  三种派生机制截然不同，彼此间无任何密码学关联可推导性。
- **强化多阶主密钥派生**：密码经预拉伸、内存硬混淆（自适应参数）、Argon2id 混合，输出 256 字节主密钥 MK，彻底告别简单循环。
- **零秘密存储**：无盐、无随机种子、无独立签名、无密钥封装块。数据库仅存密文和公开 ID。完整性由 AES-256-GCM 认证标签保证。
- **内置防篡改**：AES-256-GCM 认证加密，认证标签随密文存储，任何篡改即刻导致解密失败，浏览器拒绝显示。
- **完整笔记生命周期管理**：
  - 新增笔记：先通过 API 创建占位记录获得 id，再用派生密钥加密并更新密文。
  - 编辑笔记：解密原密文，修改后重新加密（新 IV）并更新，id 不变。
  - 删除笔记：支持软删除（标记 deleted=1，客户端过滤）和硬删除（物理移除记录）。
  - 按创建时间升序排列，分页展示标题（每页 20 条），正文按需加载。
- **严格会话安全**：60 秒无操作或页面刷新，立即擦除所有密钥与明文，返回锁定状态。
- **高级防护能力**：
  - 抗定时与缓存侧信道；
  - 自适应登录失败惩罚；
  - 内容安全策略 + 沙箱 iframe；
  - WebAssembly 密钥隔离；
  - 客户端透明操作日志与可验证完整性；
  - 操作授权令牌防越权删除。
- **越权与数据抓包天然免疫**：通过密码学授权替代传统访问控制，结合 TLS 1.3 与认证加密，即使通信被完全解密，攻击者也只能获得无法破解的密文。

## 3. 安全设计详述

### 3.1 零信任架构
- **客户端角色**：浏览器承载全部密码学模块（编译为 WebAssembly 的密码库、Web Workers 并行计算）。负责主密钥派生、笔记密钥派生、AES-256-GCM 加密/解密、操作授权令牌生成、日志签名等。
- **服务端角色**：Cloudflare Worker 仅暴露一组 RESTful 端点（详见第 8 节），所有端点均不接收或返回明文、密钥材料、盐或签名。Worker 环境变量或 D1 数据库本身不持有任何有助于解密的秘密。
- **数据库存储字段的安全性**：
  - `verification_token`：密码的 SHA-224 哈希，专用于密码验证，与加密密钥派生过程密码学隔离（算法不同，无法互推）。
  - `operation_token_hash`：操作授权令牌的 SHA-256 哈希，用于验证写操作权限，令牌本身不在服务器存储。
  - `encrypted_meta_packet`、`encrypted_body`：经过 AES-256-GCM 加密的密文，内部包含随机 12 字节 IV、密文和 16 字节认证标签，整体以 Base64 编码存储。
  - `id`：整数，用于标识笔记，也是笔记密钥派生的输入之一，公开无风险。
- **通信安全**：浏览器与 Worker 之间所有通信均通过 HTTPS (TLS 1.3) 加密，外界无法窃听或篡改传输中的密文或令牌。

### 3.2 强化多阶主密钥派生（密码 → MK）
主密钥 MK（256 字节）由用户密码经四个阶段生成，融合计算密集、内存硬和标准 KDF，彻底告别简单循环。

#### 3.2.1 阶段一：预混合与初始拉伸
- 使用 HMAC-SHA512，以硬编码应用标识符 `ctx = "S-Qrypt-v2:PreMix"` 为密钥，对密码 P 进行 256 轮迭代拉伸：
  `H0 = HMAC-SHA512(ctx, P)`，`Hi = HMAC-SHA512(ctx, Hi-1)`，i=1..256。
- 输出 `H256` 作为阶段二的初始种子，确保低熵密码被充分混淆。

#### 3.2.2 阶段二：内存硬运算与状态混淆循环（自适应参数）
- **内存配置**：根据设备能力自动选择参数（见第 9 节性能优化）。默认分配 32 MB 内存矩阵，划分为 1 KB 页。
- **并行 Worker**：创建与 `navigator.hardwareConcurrency/2` 匹配的 Web Worker，均分内存块。
- **128 轮交叉混淆**，每轮在每个 Worker 内执行：
  1. 使用 SHA-512、BLAKE2b、SHA-256 三种哈希独立生成 3 个伪随机偏移。
  2. 读取偏移处数据，与当前状态 S 混合后通过 HMAC-SHA512（密钥为轮常数）更新 S。
  3. 将新 S 的部分字节写回另外两个偏移。
  4. 可选消耗性操作（AES 空加密）以增加并行难度。
- 每 8 轮进行跨 Worker 混合：交换 1 KB 数据块并重新哈希状态。
- 128 轮后，每个 Worker 计算其分块 Merkle 树根，主线程收集所有根哈希再 SHA-512 压缩，得到中间密钥材料 `IK`（64 字节）。

#### 3.2.3 阶段三：Argon2id 混合增强
- 若浏览器支持高效 Argon2id（WebAssembly 检测通过），并行执行 Argon2id(密码, 盐=ctx, 内存=32MB, 并行度=4, 迭代=3)，输出 64 字节 `IK_argon`。
- 将 `IK` 与 `IK_argon` 进行 HMAC-SHA512 交叉混合，生成 `IK_hybrid`。
- 若环境不支持 Argon2id，直接使用 `IK` 作为 `IK_hybrid`，并在初始化时记录 `kdf_version=1`（支持 Argon2id 时版本为 2）。

#### 3.2.4 阶段四：输出淬炼与 MK 扩展
- 对 `IK_hybrid` 执行 HKDF：
  - Extract：固定盐 `SHA-256("S-Qrypt-Final")`，得 PRK。
  - Expand：info="MK"，长度 256 字节 → **主密钥 MK**。
- MK 保存在内存中，不持久化，用于后续所有笔记密钥派生及操作授权令牌生成。

### 3.3 密码验证令牌与操作授权令牌
- **验证令牌**：`verification_token = SHA-224(P)`，存储于数据库，用于客户端快速确认密码正确性。其算法与 MK 派生完全独立，无法互推。
- **操作授权令牌**：为解决无认证 API 可能被恶意调用的风险（如越权删除所有笔记），客户端从 MK 派生一个操作授权令牌：
  ```
  operation_token = HKDF-Expand(MK, info="s-qrypt-op-auth", length=32)
  ```
  然后将 `stored_hash = SHA-256(operation_token)` 在初始化时随验证令牌一起存入数据库。此后任何写操作（新增、更新、删除）均需在请求体中携带 `operation_token`。Worker 计算其 SHA-256 并与 `stored_hash` 恒定时间比对，不匹配则返回 403。令牌本身永不在服务器存储，攻击者无法伪造。

### 3.4 笔记三密钥完全异构派生（KA、KB、KC）
三条 2048 位密钥均从 MK 和笔记公开 `id` 派生，但采用三种截然不同的密码学构造，使得即便攻击者掌握其中一条密钥，也无法推导出另外两条。

#### 3.4.1 元数据密钥 KA：回旋哈希链派生
- **种子**：`seed = MK || id || "meta"`。
- **128 轮回旋混合**：
  ```
  state = seed
  for i in 1..128:
      state = SHA-512(state) XOR BLAKE2b(state)
      state = HMAC-SHA512(state, i || id)   // 引入轮数和id常数
  ```
- 取最后 state 的 256 字节作为 KA。该构造确保高雪崩效应，且每轮都与轮相关常数绑定，防止循环对称。

#### 3.4.2 正文密钥 KB：多层密钥加密派生
- 生成临时密钥 `TK = HMAC-SHA512(MK, id || "body")`（64 字节）。
- 将 TK 的前 32 字节作为 AES-256 密钥，对一个 16 字节全零明文块进行 256 次链式加密（实际可使用 CBC 模式连续加密，每次密文作为下一块明文）：
  - 获得 256 个密文块 `c0, c1, ..., c255`。
- 将所有密文块按顺序拼接成 4096 字节，然后以 256 字节为单位进行异或折叠，最终得到 256 字节的 KB：
  ```
  KB = (c0..c15) XOR (c16..c31) XOR ... XOR (c240..c255)
  ```
- 此方法依赖 AES 的强伪随机置换特性，构造出与哈希派生完全不同的密钥流。

#### 3.4.3 完整性密钥 KC：树状哈希派生
- 构建深度为 3 的 Merkle 树：
  - 叶子生成：对于 i=0..7，计算 `leaf_i = BLAKE2b(MK || id || i)`（64 字节）。
  - 第二层：`node_0 = SHA-256(leaf_0 || leaf_1)`，`node_1 = SHA-256(leaf_2 || leaf_3)`，`node_2 = SHA-256(leaf_4 || leaf_5)`，`node_3 = SHA-256(leaf_6 || leaf_7)`。
  - 根：`root = SHA-512(node_0 || node_1 || node_2 || node_3)`。
- 对 root 使用 HKDF-Expand（info="KC"）扩展至 256 字节，得到 KC。
- 该密钥用于本地完整性校验或审计签名，不参与服务器存储。

**设计意图**：三条密钥分别依赖循环异或哈希链、AES 自加密链和 Merkle 树，攻击者即使通过旁路分析复原其中一种构造，也无法跨构造推导其他密钥，且所有派生均为确定性、无存储随机材料。

### 3.5 加密与防篡改（AES-256-GCM）
- 元数据 JSON 用 KA 加密，正文用 KB 加密。每次加密生成 12 字节随机 IV（通过 `crypto.getRandomValues`）。
- 密文格式：`Base64( IV || Ciphertext || 16-byte AuthTag )`。
- 解密时，GCM 自动验证认证标签，任何对 IV、密文的篡改都会导致异常，浏览器捕获异常并拒绝加载该笔记，同时界面显示“数据完整性验证失败”。KC 可用于对解密后的内容做额外的本地签名，作为透明日志条目的一部分，但该签名不存储至服务器。

### 3.6 无存储秘密材料的彻底性
- 主密钥派生使用硬编码标识符和密码自身，不引入随机盐。
- 笔记密钥使用公开 `id` 派生，不存在每笔记随机种子。
- 完整性依赖 GCM 认证标签，不额外存储签名或 MAC。
- 操作授权令牌哈希仅验证权限，令牌本身不存储。
- 日志系统仅将操作哈希链的 Merkle 根提交至可选公开服务，根值不含秘密。
- 整个数据库泄露等价于随机数，零信息泄露。

### 3.7 抗侧信道与混淆执行
- 所有密钥比较、令牌比对使用恒定时间算法（`crypto.subtle.timingSafeEqual` 或手动实现）。
- 密钥派生循环中控制流平坦化，所有条件分支由数据驱动，不依赖直接比较指令，避免执行路径泄露密钥特征。
- 随机延迟填充：在派生开始和结束时插入随机时长的伪计算（如连续加密空块、无用哈希迭代），使每次总执行时间在 1.8~2.2 秒范围内均匀分布，消除时间指纹。
- 响应头开启跨域隔离：`Cross-Origin-Opener-Policy: same-origin`、`Cross-Origin-Embedder-Policy: require-corp`，限制高精度计时器和 SharedArrayBuffer 的暴露范围，降低 Spectre 等微架构侧信道攻击面。

### 3.8 异常行为检测与本地审计
- **自适应速率限制**：浏览器内存中维护失败计数器（仅当前会话）。连续密码错误达 5 次，自动将派生参数提升至最高档（如 64 MB 内存、200 轮），增加单次尝试时间。阈值和惩罚参数可由用户配置，正确输入后重置。
- **异常解密检测**：同一笔记在 1 分钟内被请求解密超过 10 次（极异常），浏览器临时锁定该笔记，要求用户进行额外确认（如图形验证码或延时等待），防止恶意脚本遍历内容。
- **本地安全日志**：收集安全事件（密码失败、笔记解密异常、完整性失败等），使用由 MK 派生的日志密钥加密后存入 IndexedDB（仅当用户明确开启记录功能）。提供“安全概览”界面，用户可查看最近访问时间、失败尝试及异常事件。

### 3.9 内容安全策略强化与沙箱隔离
- **严格 CSP**：Worker 响应头设置 `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; object-src 'none'; require-trusted-types-for 'script'`。禁止内联脚本和 eval，所有资源仅来自同源。
- **子资源完整性 (SRI)**：对引用的所有静态资源（.js、.wasm）计算 SHA-384 哈希，并在 `<script>` 标签中添加 `integrity` 属性。浏览器会拒绝加载被篡改的资源。
- **Trusted Types**：开启后，所有 DOM 操作必须通过 Trusted Types 对象，杜绝 DOM XSS 漏洞。
- **沙箱化密码模块**：将核心密码学代码（密钥派生、加解密）放置于一个独立的 `iframe` 中，该 `iframe` 使用 `sandbox="allow-scripts"` 属性，且 `src` 为专门的服务端点（同一 Worker，不同路径）。`iframe` 与主页面通过 `postMessage` 通信，仅传递必要的命令和结果，密钥和明文永不进入主页面 JavaScript 上下文。

### 3.10 WebAssembly 可信执行仿真
- 所有密码学原语（AES-256-GCM、SHA-512、BLAKE2b、HKDF 及自定义派生）编译为单个 WebAssembly 模块，从 JavaScript 中导入最小化 API（仅用于随机数生成和 `postMessage` 通信）。
- 主密钥 MK 和所有派生工作密钥仅存在于 Wasm 线性内存中，JavaScript 无法直接访问。Wasm 模块暴露的接口仅接受 `ArrayBuffer` 密文或明文，返回的明文通过可转移对象传递，一旦转移即从 Wasm 内存清除。
- Wasm 内部实现状态机，外部无法绕过接口直接篡改状态。模块加载时自算代码哈希与编译时嵌入的预期值比对，配合 SRI 确保运行时代码未被修改。

### 3.11 透明日志与密钥变更证明
- **操作签名链**：每次笔记的创建、更新或删除操作，客户端本地生成一条签名记录，内容包括：操作类型、笔记 ID、密文（或密文哈希）、操作时间戳、前一条记录哈希。签名密钥由 MK 和专用 info 标签派生（`SignKey = HKDF-Expand(MK, "audit-sign-key", 256)`）。签名使用 HMAC-SHA512。
- **日志存储与验证**：日志记录以加密形式存储于 IndexedDB，并定期将日志的 Merkle 树根哈希提交至一个公开的、不可篡改的存储（例如 Cloudflare Workers KV 端点，只接受哈希）。用户可通过对比本地全量日志与公开根哈希，检测服务端是否隐藏或篡改了某些笔记版本。
- **密钥变更证明**：编辑笔记导致密文变更时，日志中包含旧密文哈希和新密文哈希的关联，任何单方面回滚都会导致哈希链断裂，立即被客户端察觉。

### 3.12 越权与数据抓包防护分析
#### 越权防护
- S-Qrypt 不区分用户，无账户体系。授权完全取决于“是否持有主密钥 MK”。任何访问者必须输入正确密码才能派生 MK，进而解密数据。
- 笔记 `id` 公开，但密文由各自密钥保护。无 MK 则无法解密任何笔记，即使遍历所有 `id` 也无用。
- **写操作授权**：通过操作授权令牌（见 3.3）保护所有写端点。攻击者无法派生 `operation_token`，因而无法新增、修改或删除笔记。这彻底杜绝了“越权删除所有数据”的威胁。
- 客户端还辅以二次确认对话框、软删除优先、透明日志监控等措施。

#### 数据抓包防护
- 所有通信通过 TLS 1.3 加密，攻击者抓包仅得到密文和令牌。
- 即使 TLS 被中间人解密（如企业代理），暴露的 `verification_token` 和密文仍无法解密，因为密钥不在网络传输。
- 令牌 `verification_token` 可被用于离线暴力猜测密码，但主密钥派生的极高成本（≥2 秒，32 MB 内存）使得每次尝试昂贵。
- 建议用户使用高熵密码或可选双因素功能进一步加固。

## 6. 使用流程完整描述

### 6.1 首次初始化
1. 访问 Worker URL，检测到 `init_completed=0`，显示初始化界面，要求设置主密码并确认。
2. 用户提交后，浏览器执行强化多阶派生得到 MK，同时计算：
   - `verification_token = SHA-224(P)`
   - `operation_token = HKDF-Expand(MK, info="s-qrypt-op-auth", length=32)`
   - `operation_token_hash = SHA-256(operation_token)`
3. 创建测试笔记（虚拟 id=1），用 MK 和 id=1 按异构方法派生 KA、KB，生成随机测试正文，加密得到 `encrypted_meta_packet` 和 `encrypted_body`。
4. 调用 `POST /api/init`，发送 `verification_token`、`operation_token_hash`、测试笔记密文。
5. Worker 写入 `config` 和 `notes` 表，设置 `init_completed=1`，`kdf_version` 根据是否启用 Argon2id 设为 1 或 2。
6. 客户端读回测试笔记，解密并验证一致，初始化完成，自动进入主界面。

### 6.2 日常登录与笔记列表
1. 页面加载，检测 `init_completed=1`，显示密码输入框。
2. 输入密码，浏览器计算 `SHA-224(P)`，调用 `GET /api/token` 获取存储的验证令牌，本地恒定时间比对。
   - 不一致则提示错误，清空输入框。
   - 一致则继续。
3. 浏览器执行与初始化相同的多阶派生（根据 `kdf_version` 选择路径）得到 MK，并派生 `operation_token`，将它们暂存内存，启动 60 秒无操作计时器。
4. 调用 `GET /api/notes`，获取所有笔记的 `id`、`encrypted_meta_packet`、`is_test`、`deleted`。
5. 客户端对每条笔记使用 MK 和 `id` 派生 KA（回旋哈希链），解密元数据包，过滤 `is_test=1` 和 `deleted=1` 的记录，按 `created_at` 升序排列。
6. 前端以 20 条为页显示标题、创建时间、修改时间，底部提供“加载更多”按钮逐步展示。

### 6.3 查看正文
- 点击标题，若正文尚未下载，调用 `GET /api/note/:id` 获取 `encrypted_body`。
- 使用 MK 和该 `id` 派生 KB（多层密钥加密法），解密正文并显示。GCM 标签验证失败则提示完整性错误。

### 6.4 新增笔记
1. 点击“新建”，进入编辑界面，输入标题和正文。
2. 保存时，先调用 `POST /api/note`（请求体携带 `operation_token`），Worker 验证操作令牌后插入空白记录并返回新 `id`。
3. 客户端使用新 `id` 和 MK 派生 KA、KB，构建元数据 JSON（含当前时间），加密得到密文。
4. 调用 `PUT /api/note/:id`，在请求体中携带 `operation_token`、`encrypted_meta_packet`、`encrypted_body` 更新记录。
5. 刷新列表，新笔记出现。

### 6.5 编辑笔记
1. 点击笔记的“编辑”按钮，先获取正文密文并解密（若尚未缓存）。
2. 修改标题或正文后保存，使用相同的 `id` 和 MK 派生 KA、KB（密钥不变），生成新随机 IV 加密，调用 `PUT /api/note/:id` 更新。
3. 更新成功后刷新列表，时间戳更新。

### 6.6 删除笔记
- **软删除**：点击“删除”，确认后调用 `PATCH /api/note/:id/soft-delete`，携带 `operation_token`。Worker 置 `deleted=1`。列表刷新后不再显示。
- **硬删除**：在回收站（可选界面）长按或二次确认后，调用 `DELETE /api/note/:id`，携带 `operation_token`，永久移除记录。

### 6.7 会话超时与锁定
- 60 秒无任何用户交互事件（鼠标移动、键盘等），浏览器立即：
  - 擦除内存中的 MK、`operation_token`、所有派生密钥及解密数据。
  - 终止 Web Workers，释放 Wasm 内存。
  - 界面切换至密码锁定屏。
- 页面刷新或关闭同样触发清除（`beforeunload` 事件清理，内存自然释放）。

## 7. API 接口详细设计

所有端点前缀为 `/api`，请求和响应均为 `application/json`。写操作必须携带 `operation_token`。

### 7.1 `GET /api/token`
- **功能**：获取密码验证令牌。
- **响应**：`200 OK`
  ```json
  {
    "verification_token": "af3f8e6d..."
  }
  ```

### 7.2 `POST /api/init`
- **功能**：初始化保险箱。
- **请求体**：
  ```json
  {
    "verification_token": "...",
    "operation_token_hash": "...",
    "encrypted_meta_packet": "...",
    "encrypted_body": "...",
    "kdf_version": 2
  }
  ```
- **处理**：检查 `init_completed` 是否为 0，开启事务写入配置和测试笔记。
- **响应**：`201 Created` `{"status":"ok","test_note_id":1}`

### 7.3 `GET /api/notes`
- **功能**：获取所有笔记的元数据密文列表。
- **响应**：
  ```json
  {
    "notes": [
      {
        "id": 1,
        "encrypted_meta_packet": "...",
        "is_test": 0,
        "deleted": 0
      }
    ]
  }
  ```

### 7.4 `GET /api/note/:id`
- **功能**：获取指定笔记的完整密文（元数据和正文）。
- **响应**：
  ```json
  {
    "id": 1,
    "encrypted_meta_packet": "...",
    "encrypted_body": "..."
  }
  ```

### 7.5 `POST /api/note`
- **功能**：创建占位笔记，返回新 ID。
- **请求体**：
  ```json
  {
    "operation_token": "..."
  }
  ```
- **Worker 验证**：计算 `SHA-256(operation_token)` 与 `config.operation_token_hash` 恒定时间比较，失败返回 403。
- **处理**：`INSERT INTO notes (encrypted_meta_packet, encrypted_body) VALUES ('','')`，返回新 `id`。
- **响应**：`201 Created` `{"id": 2}`

### 7.6 `PUT /api/note/:id`
- **功能**：更新笔记密文。
- **请求体**：
  ```json
  {
    "operation_token": "...",
    "encrypted_meta_packet": "...",
    "encrypted_body": "..."
  }
  ```
- **验证**：同上操作令牌检查，再执行更新。
- **响应**：`200 OK` `{"status":"updated"}`

### 7.7 `PATCH /api/note/:id/soft-delete`
- **功能**：软删除笔记。
- **请求体**：
  ```json
  {
    "operation_token": "..."
  }
  ```
- **处理**：`UPDATE notes SET deleted=1 WHERE id=?`
- **响应**：`200 OK` 或 `404`

### 7.8 `DELETE /api/note/:id`
- **功能**：硬删除笔记。
- **请求体**：
  ```json
  {
    "operation_token": "..."
  }
  ```
- **处理**：`DELETE FROM notes WHERE id=?`
- **响应**：`200 OK` 或 `404`

**通用错误响应**：`{"error":"描述"}`，配合适当 HTTP 状态码。

## 8. 性能优化：内存混淆自适应参数
为平衡安全与体验，阶段二内存硬派生参数依据设备能力动态调整：
- 检测 `navigator.deviceMemory`（若可用）和 `navigator.hardwareConcurrency`。
- 配置策略：
  - 高配（≥8 核，≥8 GB）：内存 32 MB，128 轮，Argon2id 启用。
  - 中配（4-7 核）：内存 24 MB，100 轮，Argon2id 可选。
  - 低配（<4 核）：内存 16 MB，80 轮（仍满足 ≥60 轮安全底线），禁用 Argon2id。
- 派生总耗时控制在 1.5~2.5 秒，体验流畅，攻击成本仍指数级。

## 10. 常见问题
**Q：三个笔记密钥生成方式不同有何意义？**
A：若攻击者通过某种未知侧信道恢复出 KA，由于 KB 基于 AES 自加密链、KC 基于 Merkle 树，其无法推导其他密钥。这种异构设计实现了一钥泄露不影响其他的深度防御。

**Q：不存储任何盐和种子，如何抵抗彩虹表？**
A：主密钥派生自身具备 32 MB 内存硬计算和 256 轮预拉伸，预计算成本过高；笔记密钥通过 id 和 MK 派生，每个用户 MK 唯一，无需盐。

**Q：操作授权令牌是否会导致重放攻击？**
A：令牌在会话期内不变，攻击者若窃取某次请求可能重放。但写操作通常伴随数据变化，且可结合 Cloudflare 速率限制和客户端异常检测防止滥用。未来可升级为基于挑战-响应的一次性签名。

**Q：如果忘记密码，能否恢复？**
A：不能。零信任设计不存在后门，密码是唯一凭证。建议使用高熵密码并妥善备份。

**Q：透明日志提交的哈希会泄露隐私吗？**
A：提交的 Merkle 根为固定长度哈希，不包含笔记数量或内容信息。本地日志由用户掌控，加密存储。

**Q：浏览器不支持 Wasm 怎么办？**
A：S-Qrypt 强依赖 Wasm 实现高性能和安全隔离，若环境不支持，将提示升级现代浏览器。
